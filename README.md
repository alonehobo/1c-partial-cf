# 1c-partial-cf

Skill для агентов (Claude Code, Codex, Cursor): маленькая CF из выгрузки конфигурации 1С:Предприятие 8.3 (XML конфигуратора) только с нужными объектами и их исходными UUID — чтобы «Конфигурация → Сравнить, объединить с конфигурацией из файла…» открывалась за секунды и показывала только перенос.

Сценарий: вы поправили или добавили объекты в выгрузке и хотите перенести их в базу, не загружая всю конфигурацию. Или перенести только свои изменения модулей — отдельных методов, отдельных коммитов, — не затрагивая чужие доработки в тех же модулях.

Что попадает в CF:

- **выбранные объекты** — целиком: формы, модули, макеты, справка;
- **заглушки** — объекты, на которые ссылаются метаданные выбранных (типы реквизитов, регистры движений, владельцы, определяемые типы, картинки, стили и команды форм, таблицы и поля запросов динамических списков — с вложенными запросами и временными таблицами, `ОБЪЕДИНИТЬ`, `ВЫБОР`/`ВЫРАЗИТЬ`, ресурсами виртуальных таблиц, `.Ссылка.`/`.Регистратор.`/`.Владелец.`, общими реквизитами, — `ЗНАЧЕНИЕ()` в запросах модулей, колонки таблиц и деревьев значений формы, набор констант). У заглушки тот же UUID и сгенерированные типы, а из состава — только то, на что ссылаются, и то, без чего платформа не загрузит объект; модулей у заглушки нет;
- **корень** — тот же UUID, имя, языки и режим совместимости;
- **подсистема `_Перенос`** — в её составе только выбранные объекты.

Рядом с CF пишутся `<имя>.stubs.json` — полный список заглушек с тем, кто на них ссылается (в отчёте JSON — только число по видам и первые 30), и `<имя>.merge-settings.xml` — настройки `/MergeCfg`: выбранные объекты берутся из файла; корень и подсистема `_Перенос` — `DoNotMerge`; заглушки — `MergePrioritizingMainConfiguration` (приоритет базы), а их модули, модули сохранённых команд и форм и урезанный состав функциональных опций — `DoNotMerge`. Так заглушка базу не меняет. Без явного правила платформа объединяет и неперечисленное (корень терял `Ext/ClientApplicationInterface.xml`, заглушка затирала объект, модуль заглушки добавлял в базу свои методы), а заглушки с `DoNotMerge` большая конфигурация отвергает как «неразрешимые ссылки».

Объекты выбираются списком (`--objects Document.РеализацияТоваровУслуг Catalog.Номенклатура`) или по git (`--since HEAD` — изменённые с ревизии и новые объекты выгрузки).

Базу skill не меняет: объединение делает пользователь в конфигураторе или пакетно по явной команде.

## Только свои изменения модулей

Формат настроек объединения 1С позволяет передать для модуля патч (unidiff) — его и использует `--patch`: объект, у которого изменены только модули (объекта, менеджера, набора записей, общего модуля, формы, команды), переносится не целиком, а патчами изменённых модулей. Всё остальное в объекте — от базы.

- `--since <ревизия> [--until <ревизия>]` — изменения задачи: от `--since` до `--until` (без него — до рабочего дерева). Задачу из нескольких коммитов среди чужих соберите подряд или в отдельной ветке.
- `--target <выгрузка базы>` — выгрузка базы-получателя (полная или `ibcmd infobase config export objects`). Изменения задачи накладываются на её модули (`git merge-file`): правки базы сохраняются, а если они пересекаются с изменениями задачи, скрипт не собирает CF и кладёт модули с маркерами `<<<<<<< база` / `>>>>>>> задача` в `<имя>.conflicts/`.
- `--methods` — только изменения выбранных методов: `CommonModule.Модуль.Метод`, `Document.Д.ObjectModule.Метод`, `Document.Д.Form.Форма.Метод`, `Document.Д.Command.Команда.Метод`, `CommonForm.Форма.Метод`.
- Без `--target` патч строится на модуле как в `--since`. Патч платформа применяет строго: если в базе эти строки или их окружение изменились, `/MergeCfg` откажет («Методы, к которым не применились изменения: …») и не изменит ничего.

```
python 1c-partial-cf/scripts/partial_cf.py --export <выгрузка> --out <имя>.cf --since <начало задачи> --until <конец задачи> --patch --target <выгрузка базы>
python 1c-partial-cf/scripts/partial_cf.py --export <выгрузка> --out <имя>.cf --since HEAD --target <выгрузка базы> --methods CommonModule.ОбщегоНазначения.Метод
```

Перенос патчами проверен пакетным `/MergeCfg`.

## Установка

Скачайте архив последнего [релиза](https://github.com/alonehobo/1c-partial-cf/releases/latest) и распакуйте каталог `1c-partial-cf` в каталог skills агента, например `.claude/skills/` или `.agents/skills/`. Что изменилось — в описании релиза. Порядок работы и разбор отчёта описаны в `SKILL.md`.

Без агента скрипт запускается и сам:

```
python 1c-partial-cf/scripts/partial_cf.py --export <выгрузка> --out <имя>.cf --since HEAD
python 1c-partial-cf/scripts/partial_cf.py --export <выгрузка> --out <имя>.cf --objects Document.А Catalog.Б
```

## Как объединить

- **Окно.** «Сравнить, объединить с конфигурацией из файла…» → снять все отметки → «Действия → Отметить по подсистемам» → `_Перенос`. Заглушки, подсистему `_Перенос` и свойства корня не отмечать: отмеченная заглушка сотрёт содержимое объекта в базе.
- **Пакетно.** `1cv8 DESIGNER /F <база> /MergeCfg <имя>.cf -Settings <имя>.merge-settings.xml`.

## Требования

Только свой скрипт: внешние MCP-серверы, другие skills и пакеты Python не нужны.

- Python 3.8+ (стандартная библиотека), git — для `--since` и `--patch`.
- Платформа 1С 8.3 с `ibcmd` (ищется в `Program Files\1cv8\<версия>\bin` и `/opt/1cv8/<арх>/<версия>`, или `--ibcmd`).
- Выгрузка конфигурации в файлы (XML конфигуратора) — полная, как у базы.

## Ограничения

- Ссылки из кода BSL не отслеживаются (кроме `ЗНАЧЕНИЕ(…)` в текстах запросов): объект, на который ссылается только код, добавьте в `--objects` сам.
- Удаление объектов и изменения свойств корня CF не переносит — скрипт их перечисляет.
- Объект без `--patch` переносится целиком: изменения этого объекта в базе после выгрузки перезапишутся.
- Правило `DoNotMerge` для свойства платформа принимает, только если в базе и CF оно различается: если модуль, непустой в выгрузке, в базе пуст, `/MergeCfg` откажет («Неизмененные свойства: …») — пересоберите CF из выгрузки, совпадающей с базой.

Проверено на 8.3.27 (Windows): пакетное и интерактивное объединение; выгрузка заглушек и выбранных объектов до и после `/MergeCfg` на полной типовой конфигурации совпадает побайтно (в том числе когда модули команд и форм заглушек отличаются от базы); перенос патчами трёх больших модулей (11, 1,7 и 8,9 тыс. строк) и выбранного метода; сборка CF по 417 объектам с ручными запросами динамических списков двух крупных типовых конфигураций.
